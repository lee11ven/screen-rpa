# 多轮滚动 + 多轮（最近）定位：现有能力对齐版（工作流优先）

> 目标：将“先在外层找到锚点，再在内层继续查找并执行最近邻操作”的任务抽象为可复用执行框架。  
> 范式：`orchestration_engine` 工作流编排（`loop-container` + `action` + `if` + `wait`）为主，`lowcode_function` 仅做轻量数据整理。  
> 适用：无 DOM、位图自动化（mstsc/远程桌面/桌面应用）场景。

---

## 1. 方案定位（基于当前实现）

- 使用现有能力组合（均已在工作流 action 层映射）：
  - 子图定位：`system.image_locate_center` / `system.image_click_center`（底层 `getxy.match`）
  - 滚动：`system.mouse_scroll`
  - 点击：`system.mouse_click`
  - 等待：`wait` 节点 + 图像存在条件（`image_exists` / `sub_image_exists`）
  - 循环：`loop-container`
- 不依赖 DOM，不依赖 `scrollTop`，适配 mstsc/位图自动化场景。
- 当前 lowcode 运行时是受限内建环境，不支持在 lowcode 内直接 `import` 并调用 `execute_event`；因此主链路应落在工作流节点上，而不是把全流程写进 lowcode。

### 1.1 现状能力边界（必须遵守）

- `lowcode_function` 内不可直接依赖 `from bin import execute_event`、`capture_fullscreen_or_region` 这类导入调用。
- 编排层已稳定支持的系统动作见 `backend/README.md` 的映射表：鼠标、键盘、图像定位、窗口、剪贴板、命令执行。
- OCR 当前在 `bin` 层有能力（`ocr.recognize`、`ocr.locate_text`），但尚未形成独立 `system.ocr_*` action。若必须用 OCR，可走 `system.exec_command` 包装命令方式（建议作为补充路径，而非主路径）。

---

## 2. 工作流节点设计（最小可用，推荐）

建议使用 `loop-container` 承载“多轮滚动定位”主循环，lowcode 只保存/整理上下文：

1. `action`（可选）：窗口激活、初始点击、预滚动等“起手稳定化”动作。  
2. `loop-container`：每轮执行“定位判断 -> 分支 -> 滚动/推进”。  
3. `if`：根据节点结果决定“继续下一阶段 / 继续滚动 / 失败退出”。  
4. `action`：最终命中后点击目标。  
5. `lowcode_function`（可选）：将关键结果归档到 `ctx`（如命中轮次、阶段状态）。

说明：
- 节点级重试可直接复用 `RuntimeExecutor._exec_action` 的 `retry_times` 与 `on_error` 机制。
- 阶段化可通过“多段 loop-container 串联”实现：先外层锚点 loop，再内层目标 loop。

---

## 3. 工作流入参与上下文建议（放入 `input/ctx`）

建议通过工作流输入映射进入 `ctx`，关键思想是“阶段配置化”：

```json
{
  "root_roi": [120, 140, 820, 860],
  "threshold_anchor": 0.85,
  "threshold_target": 0.85,
  "stages": [
    {
      "name": "stage_1_anchor",
      "target_image": "assets/k1s.png",
      "search_roi_key": "root_roi",
      "scroll": {"x": 920, "y": 560, "amount": -9, "max_steps": 35},
      "derive_next_roi": {
        "mode": "expand_from_box",
        "padding": {"left": 30, "top": 80, "right": 520, "bottom": 460},
        "clip_to": "root_roi",
        "save_as": "stage_2_roi"
      }
    },
    {
      "name": "stage_2_target",
      "target_image": "assets/breakfast.png",
      "search_roi_key": "stage_2_roi",
      "scroll": {"x": 920, "y": 560, "amount": -6, "max_steps": 25}
    }
  ],
  "click": {"button": "left", "clicks": 1, "interval_ms": 0},
  "max_total_rounds": 120
}
```

字段说明：
- `stages`：多轮定位主配置，按顺序执行，允许每阶段滚动与 ROI 演进。
- `derive_next_roi`：当前阶段命中后如何生成下一阶段 ROI（需要配合低代码/变量映射存储）。
- `max_total_rounds`：全局安全上限，避免死循环。

## 4. 可执行骨架（工作流 DSL 思路）

```python
# 伪代码：把“多轮滚动定位”拆为两段 loop-container
# loop A: 找外层锚点
#   action: system.image_locate_center(template=anchor_l1)
#   if found -> break
#   else -> action: system.mouse_scroll(delta=-9) + continue
#
# loop B: 找内层目标
#   action: system.image_locate_center(template=target_l2)
#   if found -> break
#   else -> action: system.mouse_scroll(delta=-6) + continue
#
# end:
#   action: system.mouse_click(x={{ctx.target_x}}, y={{ctx.target_y}})
```

> 注意：当前“最近邻候选选择”若依赖 OCR 文本几何，建议走两步：  
> 1) 先用图像锚点完成阶段推进与区域收敛；  
> 2) 再以 `system.exec_command` 调 OCR 命令做离线选择（或后续补充 `system.ocr_*` action 后替换）。

---

## 5. 失败恢复与重试建议

- lowcode 内部返回标准结构：`ok/code/message/data`，不要抛裸异常。
- 工作流节点配置建议：
  - `retry_times`: 1~2
  - `retry_interval_ms`: 300~800
  - 必要时在失败分支先执行 `system.vision_reset` 再回到 lowcode 节点。
- 常见失败码：
  - `INVALID_STAGE`
  - `NOT_FOUND_STAGE_TARGET`
  - `NOT_FOUND_CANDIDATE`
  - `EXCEEDED_TOTAL_ROUNDS`

---

## 6. 验收标准（通用）

- 用例 1：阶段 1 目标不在首屏，外层滚动后可命中并推进阶段 2。
- 用例 2：阶段 2 在阶段 1 导出的 ROI 内滚动后可命中。
- 用例 3：同 ROI 多候选，按策略选出最近邻并点击正确对象。
- 用例 4：任一阶段失败时，返回可诊断失败码，不发生误点。

---

## 7. 实施顺序（建议）

1. 先固定 `root_roi` 与阶段 1 参数。  
2. 再加入 `derive_next_roi`，验证多阶段 ROI 传递。  
3. 接入 `action_selector` 的候选选择策略。  
4. 最后挂工作流重试/告警分支。  

---

## 8. 示例映射（把具体业务映射到通用参数）

示例（对应“先找 K1S，再找 Breakfast，最后点最近 CN￥”）：

- `stages[0].target_image = "assets/k1s.png"`，并导出 `stage_2_roi`。  
- `stages[1].target_image = "assets/breakfast.png"`，在 `stage_2_roi` 里滚动查找。  
- `action_selector.candidate_text = "CN￥"`，`anchor_stage = "stage_2_target"`。

## 10. 参数模板库（可复用）

> 用法：以下模板可直接作为 `ctx` 输入基线。上线前只需替换 ROI、子图目标、滚动参数与阈值。  
> 约定：`root_roi` 为顶层工作区；`stages` 按顺序推进；`action_selector` 负责最终动作对象选择。
> 对齐说明：模板中的 `action_selector.candidate_text` 属于“增强能力”字段；在当前版本可先仅使用 `stages + 点击` 主链路，或用 `system.exec_command` 补 OCR 分支。

### 模板 A：双层列表（外层卡片 -> 内层明细）

适用场景：
- 外层列表先定位锚点项（如用户/卡片名）。
- 进入该项可视区域后，在内层查找二级目标并对附近候选执行点击。

```json
{
  "root_roi": [120, 140, 820, 860],
  "ocr_min_confidence": 0.5,
  "max_total_rounds": 120,
  "stages": [
    {
      "name": "outer_anchor",
      "target_image": "assets/anchor_l1.png",
      "search_roi_key": "root_roi",
      "scroll": {"x": 920, "y": 560, "amount": -9, "max_steps": 35},
      "derive_next_roi": {
        "mode": "expand_from_box",
        "padding": {"left": 30, "top": 80, "right": 520, "bottom": 460},
        "clip_to": "root_roi",
        "save_as": "inner_roi_l2"
      }
    },
    {
      "name": "inner_target",
      "target_image": "assets/target_l2.png",
      "search_roi_key": "inner_roi_l2",
      "scroll": {"x": 920, "y": 560, "amount": -6, "max_steps": 25}
    }
  ],
  "action_selector": {
    "candidate_text": "CANDIDATE",
    "anchor_stage": "inner_target",
    "candidate_roi_key": "inner_roi_l2",
    "same_row_delta_px": 36,
    "policy": "same_row_then_min_dx_then_min_dist"
  }
}
```

调参建议：
- 外层滚动建议步幅更大（`amount` 绝对值大），内层滚动步幅更细。
- `padding.right/bottom` 先放宽，误点时再逐步收敛。

### 模板 B：三层嵌套（分组 -> 子列表 -> 子项操作）

适用场景：
- 需要连续 3 层定位：L1 锚点命中后推导 L2 ROI，L2 命中后再推导 L3 ROI。
- 最终在 L3 内执行候选选择（最近邻或同行优先）。

```json
      "derive_next_roi": {

```

调参建议：
- 三层场景优先提高 `max_total_rounds`，防止中途误判失败。
- L3 的 `same_row_delta_px` 建议更小，避免跨行误选。

### 模板 C：分页 + 列表（先翻页，再页内滚动）

适用场景：
- 目标可能不在当前页，需要“页级翻动（PageDown/翻页按钮）+ 页内滚动搜索”。

```json
        "mode": "expand_from_box",

        "clip_to": "root_roi",
        "save_as": "list_roi"
      }
    },
    {
      "name": "list_target",
      "target_image": "assets/target_in_list.png",
```

- `max_pages * stages[i].scroll.max_steps` 不宜过大，避免总时长失控。

### 模板 D：仅定位不点击（审计/回归模式）

适用场景：
- 先做“只定位不执行动作”的灰度验证，确认命中正确率后再打开点击。

落地说明：
- `dry_run` 需在 lowcode 中显式支持（命中后仅返回坐标，不触发 `subclick`）。
- 推荐先跑 20~50 次回放统计命中率，再切实点模式。

### 模板选择指引（快速）

- 双层结构优先用模板 A。  
- 有“组内再组内”场景用模板 B。  
- 目标可能跨页出现用模板 C。  
- 上线前灰度验收用模板 D。  

### 公共参数基线建议

- `ocr_min_confidence`：`0.5` 起步，误识别多时升到 `0.6~0.7`。  
- `same_row_delta_px`：常见 `28~40`，字号越大取值可适当放宽。  
- `max_total_rounds`：至少大于所有阶段 `max_steps` 之和，建议再加 20% 冗余。  
- 滚动 `amount`：外层用大步（如 `-8~-12`），内层用小步（如 `-4~-7`）。
